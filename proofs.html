01 / Protocol

Une preuve n'est pas une histoire.

Cette page traduit notre dossier historique d'août 2026 en protocoles ouverts. Elle précise ce qu'un tiers peut tester avec les sources publiques, ce que nos rapports antérieurs déclarent avoir déjà contrôlé, et ce qui reste non reproduit ici. Les commandes sont des procédures proposées : leur présence ne signifie pas que nous les avons exécutées à nouveau pour cette publication.

A

Observation directe

Code, message ou archive récupérés, versionnés et vérifiés localement.

B

Corroboration

Plusieurs traces concordantes, avec incertitudes explicitées.

C

Interprétation

Une lecture historique, sans prétendre prouver l'intention de l'auteur.

Règle fondamentale : il faut distinguer du code source conservé, une interface effectivement accessible, une fonction livrée dans un binaire et une utilisation réelle. Ces quatre propositions ne sont pas équivalentes.
02 / Reproduce

Construire son propre laboratoire.

Pour examiner l'histoire Git publique, utilisez un clone complet. Le dépôt Git actuel et les anciens instantanés SourceForge ne sont pas interchangeables : consignez systématiquement l'objet Git, la source et la date d'acquisition. Git doit être installé ; les commandes ci-dessous conviennent à bash et à Git Bash.

git clone https://github.com/bitcoin/bitcoin.git
cd bitcoin
git fetch --all --tags
git log --all --date=iso-strict --format='%H %aI %s' -- src/ui.cpp ui.cpp
git log --all -S 'CReviewDB' -- src/market.cpp market.cpp
# Une recherche qui ne retourne rien n'est pas une preuve d'absence.
# Certains snapshots SVN ne figurent pas dans l'historique Git courant.

Les chemins de fichiers changent selon les révisions. Si une commande ne retourne rien, cela ne prouve pas qu'une fonction était absente : vérifiez le chemin, le snapshot et la disponibilité de l'historique SVN importé.

Calculer l'intégrité d'une archive

# Linux / macOS / Git Bash
sha256sum fichier.zip

# Windows PowerShell
Get-FileHash -Algorithm SHA256 .\fichier.zip

# Comparer uniquement à l'empreinte de CE fichier exact.
# Ne pas attribuer à une reconstruction le hash d'un original.
03 / Test cases

Dix démonstrations vérifiables.

POC-01 · UI / NETWORK

Envoyer vers une IP

Chercher dans les sources historiques les branches du dialogue Send Coins, les messages checkorder et submitorder et leur traitement réseau. Vérifier ensuite si ce parcours figurait dans une distribution donnée.

git log --all -S 'checkorder' -- src/
git log --all -S 'submitorder' -- src/
POC-02 · MARKET

Le prototype de marketplace

Rechercher CProduct, CReview, CReviewDB, mapProducts et vOrderForm. Séparer les structures de données, les contrôles graphiques et la persistance réellement terminée.

git log --all -S 'vOrderForm' -- src/
git log --all -S 'CReviewDB' -- src/
POC-03 · SCRIPT

Les opcodes désactivés

Comparer script.cpp avant et après la révision historique r131 : OP_CAT, OP_SUBSTR, OP_LEFT, OP_RIGHT et autres opérations. Ne pas confondre ce retrait avec le correctif monétaire r132.

git log --all -S 'OP_CAT' -- src/script.cpp
git log --all -S 'OP_SUBSTR' -- src/script.cpp
POC-04 · CONSENSUS

Quand apparaît la limite de 1 Mo ?

Vérifier séparément MAX_SIZE = 0x02000000 et MAX_BLOCK_SIZE = 1000000. Le dossier situe la règle spécifique à r103, le 15 juillet 2010 ; son contexte doit être relu dans le code de cette révision.

git log --all -S 'MAX_BLOCK_SIZE' -- src/
git log --all -S '0x02000000' -- src/
POC-05 · WALLET

Confidentialité du change

Retrouver l'introduction de GetRand(2) pour la position de sortie et MakeNewKey() pour une nouvelle clé. Comparer les constructions de transaction avant et après, sans conclure que toutes les anciennes transactions sont identifiables.

git log --all -S 'fChangeFirst' -- src/
git log --all -S 'MakeNewKey' -- src/
POC-06 · DISCOVERY

IRC n'était pas l'unique démarrage

Comparer GetMyExternalIP, ConnectNode, AddAddress, les seeds et les options -noirc/-connect. Identifier ce qui sert à connaître sa propre IP, trouver des pairs ou établir une connexion.

git log --all -S 'GetMyExternalIP' -- src/
git log --all -S 'AddAddress' -- src/
POC-07 · SOURCEFORGE

Restaurer l'ascendance SVN

Le rapport historique revendique 33 événements de copies/déplacements restaurés concernant 42 fichiers. Pour reproduire, récupérer les journaux SVN d'origine, vérifier copyfrom_path et copyfrom_revision (dont r22→r26), puis comparer les SHA des contenus.

# Avec une sauvegarde SVN accessible :
# Prérequis : dépôt SVN complet obtenu et provenance validée.
# Exécuter uniquement après avoir fixé sa vraie URL :
svn log -v -r 22:26 <URL_SVN_VERIFIEE>
# Source non hébergée ici ; pas de preuve reproductible en l'absence du miroir.
POC-08 · MAIL

Comparer HTML et mbox

Notre bilan rapportait 11 784 pages HTML, 10 782 correspondances exactes par Message-ID, 1 002 pages non appariées et 1 009 identifiants mbox sans page associée. Il faut reconstruire des ensembles normalisés avant de recalculer ces nombres.

# Pseudocode pour corpus déjà parsés :
html_ids = set(parsed_html_message_ids)
mbox_ids = set(parsed_mbox_message_ids)
print(len(html_ids & mbox_ids))
print(len(html_ids - mbox_ids))
print(len(mbox_ids - html_ids))
# Contrôler séparément les doublons HTML.
POC-08 / Correctif
Rectification du PoC-08 : un ensemble Python set ne permet pas de compter les pages HTML lorsque plusieurs pages portent le même Message-ID. Nous publions maintenant un comparateur qui conserve les lignes HTML distinctes et compte séparément les identifiants mbox uniques. Les statistiques 2026 restent historiques tant que les fichiers de base ne sont pas fournis.

05 / Scientific limits

Ce que nous ne pouvons pas encore démontrer.

Conversations IRC

La présence d'une archive S9 ne permet pas d'attribuer des messages à Satoshi. Il faut d'abord analyser les lignes originales, le canal, l'horodatage, les pseudos et d'éventuelles corroborations.

Le départ de Satoshi

La faille monétaire de 2010 et le retrait de 2011 sont documentés, mais aucune source présentée ici ne prouve que l'une a causé l'autre.

Les images d'époque

Les six illustrations du reportage principal sont des reconstructions fondées sur le code, pas des captures authentifiées de 2009.

Confidentialité : cette page ne publie ni scripts privés, ni adresses personnelles, ni journaux de travail, ni données sensibles. Les références publiques de personnes historiques ne constituent pas une attribution de l'identité réelle de Satoshi.

07 / Revision fieldbook

Démontrer les découvertes manquantes

Ces quatre protocoles complètent les dix premiers PoC. Les événements viennent des audits Phase 6 et Phase 9, sans preuve qu'ils aient été recalculés dans la présente publication. Les tests exigent les snapshots SVN exacts, non des mots-clés trouvés dans la version actuelle de Bitcoin Core.

POC-11 · SVN r15

Minage multiprocesseur et change

Comparer la révision du 21 octobre 2009 à son parent : vérifier l'évolution du minage, l'ordre des sorties de transaction et la création d'une clé fraîche. Consigner le résultat de chaque test séparément.

POC-12 · SVN r64 → r180

La disparition incomplète du Market

Après r64, vérifier l'absence de certains écrans commerciaux tout en recherchant checkorder, submitorder et vOrderForm dans le snapshot r180. Prouver la persistance d'une chaîne ne démontre pas la fonctionnalité complète ni son exploitation effective.

POC-13 · SVN r109 / r141

Le temps réseau devient borné

Comparer les ajustements de l'horloge : la borne de 70 minutes est attestée au plus tard à r109 ; r141 ajoute un avertissement sur les grands écarts. Ne pas confondre présence à une révision et date d'invention exacte.

POC-14 · trunk@22 → multiplatform@31

Retrouver les différences du port Linux

Rejouer le comparatif d'arbres : 47 fichiers côté tronc, 59 côté multiplateforme, 13 ajouts, 14 modifications, 1 retrait et 32 inchangés ; les chiffres de notre étude demeurent des points de contrôle historiques, pas les sorties d'un programme fourni ici.

Empreintes Windows à comparer

Les deux DLL documentées possèdent des SHA-256 distincts ; leur correspondance peut démontrer un même composant de compilation distribué, non identifier une personne. Voir les empreintes et leur provenance dans le registre public.

POC-16 / SHA-256 evidence

Vérifier les archives S1 à S9 sans les confondre avec les rapports.

Ce protocole est désormais exécutable localement sur les fichiers historiques que vous aurez réellement récupérés. Le vérificateur compare chaque archive au manifeste public, signale les fichiers manquants et inspecte facultativement la liste des membres ZIP/TAR sans extraction. Aucun téléchargement ni aucune vérification des neuf originaux n'est effectué automatiquement par notre site.

python reproduce/verify_archives.py \
  --directory CHEMIN_VERS_ARCHIVES \
  --manifest evidence/ARCHIVE-MANIFEST.csv \
  --inspect-members \
  --output audit.json

# Statuts possibles : MATCH, MISMATCH, MISSING,
# UNSAFE_ARCHIVE, UNSAFE_FILE, ARCHIVE_ERROR.

Les tests unitaires de ce vérificateur utilisent uniquement des fichiers synthétiques : ils démontrent la logique de calcul et l'absence de faux PASS, mais ne valident pas les archives de 2009–2018. Le rapport historique annonçait 8/9 empreintes concordantes ; aucune n'a été recalculée lors de la présente passe.
